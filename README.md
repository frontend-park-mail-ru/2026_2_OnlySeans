# 2026_2_OnlySeans

### Локальный запуск и сборка

- `npm ci` — установить зависимости из lock-файла.
- `npm run dev` — запустить Webpack Dev Server на `http://localhost:3000`.
- `npm run build` — проверить TypeScript и собрать приложение через Babel и Webpack в `dist/`.
- `npm start` — после сборки открыть приложение на `http://localhost:8000`. Сервер раздаёт `dist/` и пересылает запросы к API на `http://127.0.0.1:8080`. Порт можно задать через `PORT`, адрес бэкенда — через `API_PROXY_TARGET`.
- `npm run test:offline` — проверить сборку, service worker и отправку изменений после подключения к сети.

PostCSS работает до `css-loader`. В исходниках `@media (--reduced-motion)` и `@media (--short-auth)` используются как общие условия. На этапе сборки они превращаются в стандартные медиа-запросы.

### Прямое подключение к API

По умолчанию запросы идут через прокси фронтенда. Для прямого взаимодействия между разными origin задайте `API_ORIGIN` перед запуском Webpack. Значение содержит только протокол, хост и порт, без пути и завершающего `/`:

```powershell
$env:API_ORIGIN = 'http://localhost:8080'
npm run build
npm start
```

Переменная встраивается в сборку; после изменения нужна пересборка. Для возврата к прокси удалите переменную через `Remove-Item Env:API_ORIGIN` и пересоберите приложение. `API_PROXY_TARGET` задаёт адрес сервера только для режима прокси.

Бэкенд должен разрешать точный origin фронтенда в `server.allowed_origins`, включая порт, и возвращать `Access-Control-Allow-Credentials: true`. Фронтенд отправляет запросы с `credentials: 'include'`. Cookie `session_id` устанавливает сервер с `HttpOnly`, `SameSite=Lax` и сроком действия: её значение не хранится в JavaScript. Такой cookie подходит для разных портов одного хоста или поддоменов одного сайта; для API на другом сайте требуется согласованная настройка cookies на бэкенде. `localhost` и `127.0.0.1` при запуске не смешивайте.

Service worker кеширует публичные данные только настроенного API, личные запросы проходят в сеть. Принудительное обновление использует `cache: 'reload'`, поэтому при прямом запросе не нужен дополнительный CORS-заголовок. Проверка сессии после возврата во вкладку объединяет параллельные запросы и отбрасывает ответы, начатые до входа или выхода. Ответ `401` при выходе очищает уже истёкшую сессию, а сетевая ошибка сохраняет текущий аккаунт.

`npm run test:auth` проверяет валидацию, гонки запросов сессии, ошибки и параметры прямых запросов. `node test-service-worker.cjs` запускайте с тем же `API_ORIGIN`, с которым собран `dist`.

На локальном Go-бэкенде с отдельными PostgreSQL, Redis и S3 проверены регистрация, успешный и неуспешный вход, конфликт имени пользователя, выход и сохранение cookie после закрытия и повторного открытия браузера. Проверки выполнены при ширине 1440 и 375 px через прямые запросы между `http://127.0.0.1:3011` и `http://127.0.0.1:8080`. Проверены разрешённый preflight с cookies и отсутствие разрешения для постороннего origin. Это проверка авторизации; остальные пользовательские сценарии требуют отдельного интеграционного прогона.

### Проверка офлайн-режима

1. Запустите бэкенд и production-сборку фронтенда. Войдите, откройте каталог, фильм, актёра и профиль. Дождитесь загрузки данных. Service worker включён для production-сборки на HTTPS и localhost.
2. В инструментах разработчика переключите сеть в режим Offline. Обновите страницу и перейдите по уже открывавшимся маршрутам. Приложение возьмёт HTML, CSS, JavaScript и ранее загруженные данные из кеша.
3. Поставьте оценку или сохраните отзыв офлайн, затем верните сеть. Изменения будут отправлены для того же аккаунта. Если серверная версия отзыва изменилась, локальный текст останется доступен в форме.
4. Вход, регистрация, выход и изменение данных профиля требуют связи с API. Manrope хранится локально и входит в офлайн-кеш приложения. Внешние изображения зависят от кеша браузера. При смене аккаунта или выходе персональный кеш и очередь предыдущего аккаунта очищаются.

### Текущие изменения по Figma

Страница `/person/:id` обновлена по макетам человека в Draft pages и Mobile. На десктопе фото занимает 240 × 320 px, на телефоне — 112 × 150 px. Добавлены раскрытие биографии, карточки ролей из каталога и фильмография со строками по годам. Столбец года на десктопе имеет ширину 64 px и не переносится. Фильтр профессии и сортировка сохраняются в `role` и `sort` в URL. Список выводится порциями по 40 строк; при возврате из фильма восстанавливается прокрутка после измерения биографии.

Расширенная карточка запрашивается через `/api/people/:id`. На текущем локальном бэкенде запрос возвращает HTTP 500: `column p.original_name does not exist (SQLSTATE 42703)`. При таком сбое фронтенд запрашивает рабочий `/api/persons/:id`, показывает имя и дату рождения и явно отмечает недоступность остальных сведений. Неизвестная фильмография не показывается как пустая, статистика работ не превращается в нули. Повторная загрузка заново проверяет расширенный API. Если базовый API тоже недоступен, показывается ошибка страницы; его 404 означает отсутствие человека.

Текущий API содержит только работы из каталога. Поэтому фильтр «Только в каталоге» недоступен; награды, рост, совместные работы, подписки и избранное персон не подставляются из демонстрационных данных. Вместо кадров персонажей карточки используют полученные постеры. Ссылкой на человека можно поделиться через системное меню либо копирование в буфер.

На реальном Go-сервере проверены частичная карточка, повтор запроса, 404 и офлайн-перезагрузка основных данных. Полная биография и фильмография проверены на ответах с текущей структурой API при ширине 1440, 1024, 768, 412 и 375 px; их успешная интеграция с расширенным endpoint пока заблокирована ошибкой сервера. `npm run test:person` проверяет возраст, некорректные даты, объединение ролей, сортировку и резервную загрузку основных данных. Публичный кеш service worker включает `/api/persons` и `/api/persons/:id`. Внешние фотографии и постеры зависят от кеша браузера.

Карточка `/film/:id` обновлена по Draft pages и Mobile: рейтинг находится в шапке, на телефоне используется кадр высотой 420 px, постер 96 × 144 px, ряд действий и навигация к описанию, актёрам и отзывам. Характеристики на телефоне сворачиваются. Оценка открывается в нативном диалоге, который на мобильном экране выглядит как нижняя шторка. При закрытии фокус возвращается на кнопку «Оценить».

Оценки используют `/api/films/:id/rating` и `/api/films/:id/rating/me`. Отзывы используют текущие GET/POST `/api/films/:id/reviews` и PUT/DELETE `/api/reviews/:id`. Заголовок проверяется на 3–255 Unicode-символов, текст — на 50–20 000. Ошибка отправки сохраняет введённый текст; конфликт версии требует обновления страницы. Публичный API отзывов передаёт идентификатор автора, но не имя и оценку: для чужих отзывов показывается «Пользователь #ID», для своего используются данные текущей сессии. Демонстрационные подписи из `review-authors.json` больше не подставляются.

После удаления отзыва доступна отмена в течение пяти секунд. API не имеет восстановления удалённой записи, поэтому отмена создаёт отзыв с теми же заголовком, текстом и признаком спойлеров; идентификатор и дата меняются. Смена аккаунта блокирует отмену и применение запоздавших изменений к новой сессии.

На локальном Go-бэкенде проверены списки, постановка и удаление оценки, создание и изменение отзыва, конфликт версий и отмена удаления при ширине 1440, 412 и 375 px. Дополнительно проверены скелетон, ошибка с повтором запроса, настоящий 404, офлайн-перезагрузка, очередь оценки и её отправка после восстановления сети, отказ при истёкшей cookie. `npm run test:film` проверяет границы валидации и обработку страниц отзывов.

Ограничение текущего бэкенда: `/api/films/1/people` отвечает HTTP 500, в логе — `SQLSTATE 42703` при запросе `person_catalog.film_persons`. Фронтенд показывает ошибку и повтор запроса. Код и миграции бэкенда не изменены. Кадры API также не передаёт, соответствующий пункт недоступен. Внешние постеры могут не загружаться без сети.

Токены `--text-size-40` и `--border-glass` добавлены из макетов фильма. Иконки рейтинга, мобильных действий и закрытия экспортированы из Figma и сохранены локально.

Обновлены общий каркас, главная и мобильная навигация по Draft pages и Mobile. Главная показывает скелетон во время запроса, пустое состояние при пустом каталоге и кнопку повторного запроса при ошибке. Категории ленты фильтруют реальные данные, следующая порция карточек появляется при прокрутке или по кнопке «Показать ещё».

Поиск `/search?q=...` сопоставляет запрос с названиями фильмов и именами персон из `/api/films` и `/api/persons`. История хранит до восьми запросов; её можно очистить. `/genres` строится по жанрам фильмов, выбор жанра открывает `/films?genre=...`.

Каталоги `/films` и `/series` поддерживают включение и исключение жанров, сочетания «все выбранные» / «хотя бы один», диапазон лет, возраст, минимальный рейтинг и сортировку. Параметры сохраняются в URL; вид списка — также в настройках. Поповер на десктопе превращается в шторку на мобильном экране. До «Показать» изменения остаются черновиком; Esc, кнопка закрытия и клик вне окна отменяют их. При возврате из карточки фильма восстанавливаются позиция прокрутки и количество показанных карточек.

Фильтрация выполняется по полному каталогу, полученному через существующую пагинацию `/api/films?details=true`. Следующие карточки отображаются порциями по 40 без дополнительных сетевых запросов. Рейтинг берётся из `/api/films/:id/rating`, кешируется на минуту и загружается не более чем шестью запросами одновременно в одной операции. Сортировка по популярности использует число оценок, по рейтингу — среднюю оценку; фильмы без оценок идут последними. На мобильном экране оценки видимых карточек загружаются в фоне. Страны отсутствуют в текущем контракте каталога, поэтому соответствующая кнопка недоступна.

Календарь премьер на `/upcoming` пока показывает состояние недоступности: текущий API передаёт год выпуска, но не даты премьер. Полный календарь, напоминания, расширенные фильтры поиска, рейтинг и «Топ-250» в мобильной ленте остаются отдельными задачами. Остальные экраны ещё требуют сверки с Draft pages и Mobile.

Адаптив существующих маршрутов проверен в Chrome при размерах 320×740, 375×667, 412×915, 667×375, 768×1024, 1024×768 и 1440×1000. Проверены главная, каталог фильмов и сериалов, подборки и отдельная подборка, жанры, поиск и длинная история запросов, состояние премьер, три пользовательских списка, профиль и его формы, фильм, персона, вход, регистрация и 404. Подборки используют одну колонку на телефонах, две на планшетах и три на широком экране. Фотография в настройках профиля находится внутри элемента загрузки, а не позиционируется относительно страницы. На телефонах поля имеют шрифт не меньше 16 px, сообщения профиля учитывают нижнюю навигацию. Режим списка, фильтры и окно оценки проверены на тех же размерах; горизонтального переполнения страницы нет. Для воспроизводимых состояний использовались ответы API с тестовыми данными. С реальным локальным Go API дополнительно проверены избранное профиля, ошибка выбора фотографии, отмена редактирования, сохранение данных и перезагрузка при ширине 320 и 768 px. Проверка на физических устройствах и в Safari не выполнялась. Это проверка адаптива реализованных экранов, а не подтверждение реализации всех функций макетов.

Для каркаса добавлены токены `--content-width`, `--content-gutter` и `--mobile-gutter`. Цвета скелетонов, градиент кнопок и длительности анимаций взяты из ТЗ; существующие имена токенов сохранены.

Токен `--surface-token: #12141a` добавлен из градиента круглого жетона пустого состояния в Draft pages. Новые иконки фильтров, сортировки, рейтинга и пустых состояний экспортированы из Figma.
